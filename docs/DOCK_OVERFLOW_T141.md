# T-141 native dock overflow

The owner screenshot shows the action tier contained by the dock while Home, Debt and part of Transactions occupy the visible navigation row; the last two targets are clipped. The earlier HTML sizing review did not establish native layout behavior.

Source evidence: the dock clipped overflow but had no explicit width; its row was stretched implicitly and measured the dock rather than the row. Each unselected target used `flex: 1` plus `minWidth: 44`; the selected target used `width: 160`. NativeAppearance's `mapStyle` flattens these styles and only remaps colors; it does not remove or normalize flex properties. The installed Yoga `Node.cpp` resolves positive numeric flex to grow and a zero basis under non-web defaults, while default shrink is zero. Thus these targets rely on a definite parent main-axis constraint and Yoga's distribution, not CSS button sizing. The screenshot establishes the overflow, but without a native layout trace it does not uniquely establish which ancestor or Yoga measurement produced the oversized row; claiming a proven runtime root cause would be misleading.

The fix gives the dock a width bounded by the window and horizontal safe-area insets, measures the row itself, and computes explicit widths from the lesser of that measurement and the bound, less the dock borders and row padding. It does not use flex growth or intrinsic minimums to size targets. The 160-point selected pill is used only when the row has at least 336 points of inner width and text scaling permits it; otherwise all five targets share the available width and the caption identifies the selection. Before measurement, widths are zero rather than an overflowing speculative layout. At widths below 220 points of inner space, five 44-point targets cannot physically fit; targets shrink to remain contained. Normal and narrow phone widths support the minimum.
